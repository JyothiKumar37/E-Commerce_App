# E-Commerce Platform

A production-style e-commerce application built as Node.js microservices and deployed on **Amazon EKS** (`ap-south-1`) with GitOps, full observability, and a **managed AWS RDS PostgreSQL** database.

- Storefront: `https://jeds.shop`
- API gateway: `https://jeds.shop/api`

---

## Architecture

- **Storefront:** `web`
- **API gateway:** `api-gateway` — the single public entry point; routes to the backend services
- **Microservices:** `account`, `cart`, `inventory`, `order-status`, `payment`, `place-order`, `product-review`, `recommendation`, `recommendation-generation`, `search`, `shipping`
- **Data stores:**
  - **PostgreSQL** — managed **AWS RDS** (primary relational store)
  - **Redis** — in-cluster (cart / cache)
  - **Elasticsearch** — in-cluster (product search)
- **Ingress:** `ingress-nginx` behind an AWS NLB, TLS-terminated, with a Route 53 alias for `jeds.shop`
- **GitOps:** ArgoCD continuously syncs `k8s/` from `main`
- **CI/CD:** GitHub Actions — build & test, OIDC → ECR push, image scan, and automated GitOps deploy PRs
- **Observability:** Prometheus, Grafana, Loki (logs), Tempo (traces), Alertmanager
- **Infrastructure as Code:** Terraform — VPC, EKS, managed node group, ECR, and RDS, with remote state in S3

## Database — managed AWS RDS PostgreSQL

The platform runs against a managed **RDS PostgreSQL 16** instance instead of an in-cluster Postgres pod, for durability (automated backups + point-in-time recovery), encryption, and operational safety.

### RDS configuration (`terraform/rds.tf`)

- Free-tier `db.t4g.micro`, 20 GB gp2, single-AZ
- **Encrypted at rest**; **TLS enforced** in transit (`rds.force_ssl`)
- Automated backups + PITR (retention within the AWS Free Plan cap)
- **Not publicly accessible** — the security group allows port `5432` **only from the EKS node security group** (a source SG, no CIDR, no public exposure)
- Master password generated by Terraform (`random_password`) — never hand-typed or committed
- The assembled connection string is a **sensitive** Terraform output (`rds_database_url`)

### How the app connects

- Every service reads one `DATABASE_URL` key from the `ecom-secrets` Secret; only the host changes (now the RDS endpoint) — **no application code change**.
- Connections use TLS via `PGSSLMODE=no-verify` (encrypted; the RDS CA does not need to be bundled).
- A `postgres` **ExternalName** Service aliases the old in-cluster hostname to the RDS endpoint, so name-based clients (e.g. the migrate Job) resolve transparently.

### RDS-aware deployment

`scripts/deploy-eks.sh --use-rds` (auto-detected when the `rds_endpoint` Terraform output exists):

1. Injects the RDS `DATABASE_URL` into `ecom-secrets` (via a private temp file — never on the command line)
2. Skips the in-cluster Postgres deployment
3. Creates the `postgres` → RDS ExternalName alias
4. Excludes the Postgres manifests from the ArgoCD app so GitOps won't recreate the pod

## Deploy from scratch

**Prerequisites:** `aws`, `kubectl`, `helm`, `jq`, `terraform >= 1.10`; a populated `k8s/ecom-secrets.yaml`; images pushed to ECR (`scripts/ecr-push.sh`).

```bash
# 1. Provision infrastructure (VPC, EKS, ECR, RDS) — ~20 min
cd terraform
terraform init
terraform apply

# 2. Deploy the platform onto the cluster (RDS mode)
bash scripts/deploy-eks.sh --use-rds

# 3. Verify end to end
API_URL=https://jeds.shop/api node scripts/e2e.mjs        # 91 functional checks
API_URL=https://jeds.shop/api node scripts/oversell.mjs   # concurrency / no-oversell
```

## Verify database connectivity

```bash
# App-level: /readyz makes a live Postgres round trip
kubectl -n ecom port-forward deploy/account 8081:8081 >/dev/null 2>&1 &
sleep 2; curl -s localhost:8081/readyz; echo; kill %1

# Network: reach RDS through the ExternalName alias (no credentials needed)
kubectl -n ecom run pgready --rm -it --restart=Never --image=postgres:16-alpine \
  -- pg_isready -h postgres -p 5432 -U ecom -d ecom
```

## Teardown

Delete the ingress LoadBalancer Service **before** `terraform destroy`, or the VPC teardown fails with a `DependencyViolation` (the NLB's network interfaces stay attached to the subnets):

```bash
kubectl -n ingress-nginx delete svc ingress-nginx-controller   # wait ~60s for the NLB to disappear
cd terraform
terraform destroy
```

RDS is created with `skip_final_snapshot = true` and `deletion_protection = false`, so it tears down cleanly (no final snapshot — demo data is re-seedable).

## Terraform remote state

State is stored in S3 (`s3://ecom-tfstate-034768441662/eks/terraform.tfstate`) — **encrypted, versioned, with S3-native locking** (`use_lockfile`, no DynamoDB table). The state bucket is independent of the cluster stack and persists across teardown/rebuild cycles. Requires Terraform `>= 1.10`.

## CI/CD

- **CI (`.github/workflows/ci.yml`):** install, lint, test, and build on every change; container image scan.
- **CD (`.github/workflows/cd.yml`):** builds and pushes images to ECR using **GitHub OIDC** (no static AWS keys), then opens a **GitOps deploy PR** that bumps the image tags in `k8s/`. ArgoCD syncs on merge.

Deployed as an ArgoCD app-of-apps:

- **Prometheus** — metrics, scraping all services
- **Grafana** — dashboards
- **Loki + Alloy** — log aggregation (S3-backed)
- **Tempo** — distributed tracing (S3-backed)

## Notes & gotchas

- **RDS enforces TLS.** PostgreSQL 16's default RDS parameter group sets `rds.force_ssl=1`, so all DB clients use `PGSSLMODE=no-verify` (encrypted, without needing the RDS CA bundle).
- **Free Plan backup cap.** The newer AWS Free Tier limits backup retention below the classic 7 days, so retention is set to `1` day. Raise it on a paid plan.
- **Engine version.** AWS retires old minors; pin `db_engine_version` to an available `16.x` — check with `aws rds describe-db-engine-versions --engine postgres --region ap-south-1`.

## Production hardening (roadmap — mostly paid)

- **Multi-AZ** RDS for automatic failover
- **Longer backup retention** (7–35 days)
- **AWS Secrets Manager** for the DB password (RDS-managed, with rotation) synced via External Secrets Operator
- **`verify-full` TLS** with the RDS CA bundle (`PGSSLROOTCERT`)
- **Least-privilege DB user** (dedicated app role, not the master user)
- **Connection pooling** (RDS Proxy / PgBouncer)
- **Instance right-sizing** and read replicas
